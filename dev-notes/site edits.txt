Spaghetti reduction plan

Problem:
Presentation-critical block rules have started living in too many places: renderer branches, browser state normalization, dev-server normalization, seed JSON repair scripts, and route-specific tests. That makes small visual rules fragile because an old saved block can bypass the blueprint or a duplicated normalizer can miss one field.

Goal:
Blocks and pages stay separate. Pages choose block order and route shell. Blocks own their rendering contract. Preset-owned presentation fields should be declared once and enforced everywhere.

Pass 1:
Create one shared presentation-contract module for request-form and billboard preset rules. Replace duplicated CGA outro, Ministry Impact outro, and legacy-impact request-form repair code with calls into that shared contract. Keep the pass narrow: no visual redesign, no unrelated refactor.

Pass 2:
Route all dynamic block renderers through a shared normalize-for-render step before they build runtime config. Remove renderer-local special cases once contracts cover them.

Pass 3:
Update Admin/HUD editors so preset-owned presentation fields are locked, hidden, or reset automatically instead of being freely editable drift.

Pass 4:
Replace path/block-id if-chains in browser and dev-server state normalization with a table-driven contract pass by block kind, preset id, section class, and optional content match.

Pass 5:
Add guardrails that fail on new duplicated route-specific presentation repair functions and fail when preset blocks persist stale preset-owned fields.

Status:
Completed the pass sequence by adding `src/lib/blockPresentationContracts.js`, routing native rendering, shared block rendering, client admin state merge, and dev-server normalization through it. Added field-lock behavior for preset-owned settings and guardrail tests for duplicated route-specific presentation normalizers.
